## Часть 1. Общая Концепция

### 1.1 Что мы строим

Платформу, которая каждый день:
1. Собирает данные о самочувствии и нагрузке спортсмена
2. Проверяет, безопасно ли тренироваться
3. Генерирует персональный план тренировки с помощью ИИ
4. Даёт тренеру полный контроль и обзор над группой атлетов

Всё взаимодействие происходит через **Telegram** и **веб-браузер**. Установка приложения не требуется.

### 1.2 Два типа пользователей

**Атлет (B2C)**
- Физически активный человек: любитель, спортсмен-любитель, профессионал
- Хочет тренироваться умнее, не перегружаться, быстрее восстанавливаться
- Доступ: Telegram Bot + PWA в браузере

**Тренер / Клуб (B2B)**
- Индивидуальный тренер или спортивный клуб
- Хочет мониторить группу атлетов, получать алерты, корректировать планы
- Доступ: Веб-кабинет тренера

## Часть 2. Что должна делать система (Функциональные требования)

### 2.1 Ежедневный чек-ин атлета ✅ Реализовано

**Что:** Атлет каждое утро отвечает на 5 вопросов.

**Как:** Через Telegram-бот командой `/checkin` или кнопкой в мини-приложении.

**Вопросы (шкала Hooper):**
- Уровень энергии (1–10)
- Качество сна прошлой ночи (1–10)
- Уровень стресса (1–10)
- Усталость/болезненность мышц — DOMS (1–10)
- Боли в теле — локализация и интенсивность (VAS 0–10)

**Результат:** Система получает субъективные данные для оценки готовности атлета к нагрузке.

---

### 2.2 Автоматический сбор данных с носимых устройств ✅ Реализовано (Фаза 5.1)

**Что:** Данные о тренировках и сне подтягиваются автоматически — без ручного ввода.

**Интеграции:**
| Устройство / Сервис | Что передаётся | Как |
|:---|:---|:---|
| **Garmin Connect** | ЧСС, мощность, темп, шаги, данные сна | Webhook (авто-пуш) |
| **Oura Ring** | HRV (rMSSD), температура тела, Readiness Score | Webhook (авто-пуш) |
| **Whoop** | Strain Score, Recovery Score, данные сна | Webhook (авто-пуш) |
| **Garmin / Polar / Suunto (файл)** | Полная запись тренировки | Ручная загрузка .FIT файла |
| **BLE-пульсометр** | ЧСС в реальном времени | Bluetooth из браузера (Polar H10, Garmin HR) |

### 2.3 Медицинский контроль безопасности ✅ Реализовано

**Что:** Перед каждой тренировкой система проверяет, нет ли опасных симптомов.

**Три уровня реакции:**

| Уровень | Когда срабатывает | Что происходит |
|:---|:---|:---|
| 🚨 **Красный (Emergency)** | Боль в груди, головокружение, аритмия | Тренировки полностью заблокированы. Атлет получает сообщение: «Обратитесь к врачу» |
| 🏥 **Оранжевый (Medical Lock)** | HRV резко упал (Z-score < -2.5), острая боль в суставах (VAS ≥ 8) | ИИ не вызывается. Назначается день полного отдыха |
| ⚠️ **Жёлтый (Caution)** | Перегрузка (ACWR > 1.4), высокий DOMS (≥ 7) | Интенсивная тренировка заменяется лёгким восстановлением |

> **Важно:** Это не медицинский сервис и не телемедицина. Система помогает не навредить себе тренировками, но не ставит диагнозов и не заменяет врача.

---

### 2.4 Генерация персонального плана тренировки ✅ Реализовано

**Что:** ИИ составляет конкретный план тренировки на день.

**На основе чего:**
- Профиль атлета (вид спорта, уровень, цели, история травм)
- Результаты сегодняшнего чек-ина
- Данные с носимых устройств (HRV, нагрузка за неделю и месяц)
- Тренировочная история

**Что содержит план:**
- Тип тренировки (интервалы, темповой бег, восстановление, силовая и т.д.)
- Конкретные интервалы с целевым пульсом или мощностью
- Рекомендации по темпу и продолжительности
- Советы по питанию перед/во время/после тренировки (для нагрузок > 60 мин)
- Объяснение, почему именно такая тренировка сегодня

**ИИ-движок:**
- Основной: Google Gemini 1.5 Flash (быстрый, экономичный)
- Резервный облачный: Google Gemini 1.5 Pro (при сложных случаях)
- Локальный резерв: Phi-3-mini / Gemma-2B прямо в браузере (без интернета)
- Последний резерв: детерминированные правила (всегда даёт ответ)

### 2.5 Учёт вида спорта при расчёте нагрузки ✅ Реализовано (Фаза 5.2)

**Что:** Система понимает, что одинаковый объём нагрузки даёт разный стресс для тела в зависимости от вида спорта.

**Коэффициенты:**
- Бег: × 1.3 (высокий ударный стресс)
- Силовые тренировки: × 1.1 (умеренный стресс)
- Велоспорт / плавание: × 1.0 (базовый стресс)

**Зачем:** Даёт точнее оценивать риск перетренировки у бегунов и триатлетов.

---

### 2.6 Рекомендации по питанию и гидратации ✅ Реализовано (Фаза 5.2)

**Что:** Система рассчитывает индивидуальные потребности в питании и воде для конкретной тренировки.

**Входные данные:** Продолжительность тренировки, средний пульс, интенсивность.

**Выходные данные:**
| Нагрузка | Примерные рекомендации |
|:---|:---|
| До 60 мин | Воды достаточно |
| 60–120 мин | ~40 г углеводов/час, 500–700 мл воды/час |
| 2–4 часа | ~60–80 г углеводов/час, электролиты, 700–1000 мл/час |
| 4+ часа | Детальный план питания с натрием, кофеином и питанием на дистанции |

### 2.7 Кабинет Тренера (B2B) ✅ Реализовано

**Что:** Веб-интерфейс для тренера, работающего с группой атлетов.

**Функции:**

**Мониторинг группы**
- Сводная таблица всех атлетов с цветовой индикацией состояния (зелёный / жёлтый / красный)
- Показатели для каждого: готовность, ACWR, HRV, последняя тренировка
- Фильтрация по виду спорта и уровню готовности

**Алерты**
- Мгновенное Telegram-уведомление, если у атлета сработал тревожный показатель
- Лента алертов в кабинете с историей

**Переопределение планов ИИ**
- Тренер может изменить или отменить план для любого атлета
- **Пакетная операция**: изменить планы сразу для всей группы (например, назначить разгрузочную неделю) — в 1 действие

### 2.9 Push-уведомления через Telegram Bot ✅ Реализовано (Фаза v7.1)

**Что:** Автоматические персональные push-уведомления атлетам в Telegram.

**Возможности:**
- **Персонализированное время утреннего чек-ина (UTC)** — индивидуальная настройка времени напоминания для каждого атлета в профиле.
- **Готовность тренировки** — уведомление о сформированном плане на день с Readiness Score.
- **Экстренные Red Flag алерты** — мгновенные уведомления с инструкциями при выявлении аномалий (Level 1 Emergency / Level 2 Medical).
- **Еженедельный дайджест** — автоматический отчёт по воскресеньям (динамика ACWR, HRV trend).
- **Opt-in / Opt-out** — гибкое отключение каждого типа уведомлений через API или команды бота `/subscribe` и `/unsubscribe`.

---

### 2.10 Интеграция Strava API ✅ Реализовано (Фаза v7.1)

**Что:** Двусторонняя интеграция со Strava API для авто-импорта тренировок.

**Специфика реализации:**
- **OAuth 2.0 Flow**: Регистрация, авторизация через Strava, генерация CSRF state, надежное хранение токенов с шифрованием AES-256-GCM и авто-рефрешем.
- **Отложенный импорт (1 час)**: По push-событию `event_type=create` выгрузка тренировки выполняется ровно через 1 час после окончания — для корректного учета всех финишных правок (GPS, высоты, дистанции).
- **Обработка правок (`event_type=update`)**: Автоматическое синхронное обновление названия и метрик уже загруженных тренировок.
- **Интерактивный опрос при аномальном ЧСС**: При аномальном пульсе (≥210 bpm или >110% Max HR) система не блокирует тренировку мгновенно, а запрашивает атлета в Telegram: *«Сбой датчика»* (данные игнорируются) или *«Реальный пульс»* (запуск Red Flag триажа).

## Часть 3. Безопасность и Законодательство

| Требование | Как выполняется |
|:---|:---|
| **Персональные данные (152-ФЗ)** | Все данные граждан РФ хранятся на серверах в России (Selectel). Telegram `chat_id` и токены Strava шифруются AES-256-GCM |
| **Медицинская деятельность (323-ФЗ)** | Система не ставит диагнозов. Чёткое разграничение: рекомендации ИИ — не медицинские назначения |
| **Шифрование данных** | Имена, телефоны, токены Strava и телеметрия шифруются (AES-256). Пароли хранятся только в виде хешей |
| **Права пользователя** | Возможность отключить Strava и удалить все свои токены/данные по запросу (`DELETE /api/v1/strava/disconnect`) |
